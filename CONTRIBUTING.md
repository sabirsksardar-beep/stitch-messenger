# Contributing to Stitch Messenger

Thank you for your interest in contributing to Stitch Messenger!

## How to Contribute

### 1. Fork the Repository
```bash
git clone https://github.com/sabirsksardar-beep/stitch-messenger.git
git checkout -b feature/your-feature-name
```

### 2. Create Your Feature Branch
```bash
git checkout -b feature/amazing-feature
```

### 3. Commit Your Changes
```bash
git commit -m 'Add some amazing feature'
```

### 4. Push to the Branch
```bash
git push origin feature/amazing-feature
```

### 5. Open a Pull Request
- Describe your changes clearly
- Reference any related issues
- Include screenshots if UI changes

## Contribution Guidelines

### Code Style
- Use Kotlin best practices
- Follow Android Architecture Components
- Write clean, readable code
- Add comments for complex logic

### Testing
- Write unit tests for new features
- Run existing tests: `./gradlew test`
- Test on actual Android devices

### Security
- Never commit sensitive data (keys, passwords)
- Use `.gitignore` for local configs
- Review security implications of changes

### Documentation
- Update README if needed
- Add comments in code
- Document new APIs

## Bug Reports

When reporting bugs, include:
- Android version
- Device model
- Steps to reproduce
- Expected vs actual behavior
- Error logs (if applicable)

## Feature Requests

For feature requests:
- Describe the use case
- Explain the benefit
- Provide mockups if UI-related
- Consider security implications

## Code Review Process

1. Submit pull request
2. Code review by maintainers
3. Address feedback
4. Approval and merge
